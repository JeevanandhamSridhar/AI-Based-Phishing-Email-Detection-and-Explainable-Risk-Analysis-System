# Machine Learning & Explainability Pipeline

This document outlines the machine learning architecture, feature representation, explainability engines, and experimental evaluation protocols.

---

## 1. Baseline Phishing Classifier Pipeline

### 1.1 Architecture & Hyperparameters
- **Vectorizer:** `TfidfVectorizer`
  - `ngram_range`: `(1, 2)` (unigrams and bigrams)
  - `max_features`: 10,000 (tuned for fast, reproducible laptop inference)
  - `sublinear_tf`: `True` (dampens the influence of overly frequent tokens)
  - `strip_accents`: `'unicode'`
  - `stop_words`: `'english'`
- **Classifier:** `LogisticRegression`
  - `C`: 1.0 (L2 regularized)
  - `solver`: `'lbfgs'`
  - `max_iter`: 1000
  - `random_state`: 42 (fixed seed for deterministic reproducibility)
- **Output:** Calibrated posterior probability $P(\text{Phishing} \mid \text{Text})$ via sigmoid response function.

### 1.2 Serialization Layout
```
models/baseline/
├── model.joblib          # Trained LogisticRegression model
├── vectorizer.joblib     # Fitted TfidfVectorizer
├── metadata.json         # Training date, seed, dataset size, hyperparams
└── metrics.json          # Real evaluation metrics (Accuracy, P, R, F1, ROC-AUC, CM)
```

## 2. Explainable AI (XAI) Architecture

### 2.1 SHAP (`LinearExplainer`)
Because our baseline model is a regularized linear model operating over sparse TF-IDF vectors, `shap.LinearExplainer` computes exact analytical Shapley values without sampling approximations.
- For each token $j$, its Shapley value $\phi_j$ represents its direct additive contribution to the log-odds of the phishing classification.
- Tokens with positive $\phi_j$ strongly push the prediction toward **Phishing**.
- Tokens with negative $\phi_j$ push the prediction toward **Legitimate**.

### 2.2 LIME (`LimeTextExplainer`) Cross-Validation
- Acts as a local model-agnostic surrogate to verify that feature attributions remain stable when perturbations are applied to the text.
- Used to confirm local fidelity and ensure feature robustness.

### 2.3 Natural Language Synthesis Algorithm
To make explanations actionable for non-expert analysts, feature attributions are translated into natural language:
1. Extract top $K$ features ($K=4$) with highest positive Shapley attributions.
2. Cross-reference tokens with semantic categories (Urgency, Credential Harvesting, Financial, Impersonation).
3. Generate a structured English rationale describing which phrasing patterns triggered the classifier.
4. Always append the defensive disclaimer: *"Model-based feature attribution, not definitive legal proof."*

## 3. Module A: AI-Generated / LLM-Authored Phishing Classifier

### 3.1 Motivation (Following Opara et al., 2025)
Traditional phishing detectors evaluate whether an email is malicious. Module A addresses a distinct threat dimension: **Was the text crafted by a human or generated by an LLM?**

### 3.2 Stylometric Feature Set
The stylometric extractor operates on clean text and produces an 18-dimensional feature vector:
1. **Lexical Diversity:**
   - Type-Token Ratio (TTR): $\frac{\text{unique words}}{\text{total words}}$
   - Hapax Legomena Ratio: Words appearing exactly once divided by total words.
2. **Syntactic & Sentence Variance:**
   - Mean sentence length (word count per sentence).
   - Variance/standard deviation of sentence lengths (LLMs exhibit low variance / uniform sentence rhythms).
   - Mean word length (characters per word).
3. **Punctuation & Capitalization Ratios:**
   - Exclamation density, question mark density, semicolon/comma density.
   - Uppercase-to-lowercase character ratio.
4. **Function Word Distribution:**
   - Frequencies of formal coordinating and subordinating conjunctions (*furthermore*, *moreover*, *consequently*, *therefore*).
5. **Readability Indices:**
   - Flesch Reading Ease score.
   - Flesch-Kincaid Grade Level.

### 3.3 Training & Cross-Generator Generalization
- **Classifier:** Scikit-learn Random Forest / Logistic Regression with feature scaling (`StandardScaler`).
- **Evaluation Protocol:**
  - **In-Generator Evaluation:** Train on 70% of Generator A + Generator B data, test on remaining 30%.
  - **Cross-Generator Evaluation:** Train exclusively on Generator A + Generator B outputs; test on completely unseen Generator C outputs.
  - Transparently document the performance degradation in `docs/ai-authorship-eval.md`.

## 4. Module B: Explanation-Guided Adversarial Self-Evaluation

### 4.1 Threat Model (Following Denis & Meurant, 2024–25)
An adversary who has query access or visibility into the model's top SHAP/LIME triggers can intentionally replace high-attribution tokens with synonyms or passive phrasing that bypasses lexical filters while maintaining the underlying social engineering pretext.

### 4.2 Adversarial Evaluation Harness
1. **Trigger Extraction:** Identify the top 20 global phishing tokens from the baseline model (e.g., `verify`, `suspend`, `immediate`, `urgent`, `click here`, `password`, `billing`).
2. **Adversarial Perturbation:**
   - Select 10–15 true-positive phishing emails correctly identified by the baseline model.
   - Generate semantically equivalent rewrites that remove or replace the trigger tokens without altering the fraudulent intent.
3. **Re-Evaluation:**
   - Ingest rewritten variants through the complete pipeline (ML model + Heuristic Risk Engine).
   - Measure:
     - **ML Classifier Evasion Rate:** Percentage of samples where prediction flips from Phishing $\to$ Legitimate.
     - **Risk Engine Score Degradation:** Difference in final 0–100 score ($\Delta R = R_{\text{orig}} - R_{\text{pert}}$).
     - **Heuristic Defense Retention:** Does the multi-signal engine (URL, header, sender domain) still catch the threat even when the ML text classifier is evaded?
4. **Transparent Reporting:** All metrics and evasion examples are recorded in `docs/adversarial-eval.md` and exposed on the frontend Model Performance dashboard.
