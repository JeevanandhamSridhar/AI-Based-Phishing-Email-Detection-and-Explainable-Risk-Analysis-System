## 1. Project Overview & Research Framing

This project develops a local-first, defensive email-security analysis platform that inspects suspicious messages (`.eml`, `.txt`, or raw input) and delivers a multi-signal explainable phishing risk assessment.

### Core Architecture & Novel Scope:
While multi-signal heuristic and ML scoring is sound engineering, state-of-the-art literature (2025–2026) demonstrates that standard pipelines (heuristics + ML + SHAP/LIME) are already common. This project addresses two critical unaddressed gaps within local student-deployable systems:

1. **AI-Generated / LLM-Authored Phishing Identification (Module A):**
   A secondary stylometric classifier designed to estimate whether phishing text was generated by an LLM or written by a human. Importantly, the system explicitly tests and reports both in-generator accuracy and cross-generator generalization drops rather than obscuring cross-model degradation.
2. **Explanation-Guided Adversarial Self-Evaluation (Module B):**
   A dedicated adversarial testing harness that uses the model's own top SHAP/LIME explanatory triggers to formulate semantically equivalent paraphrased attacks, evaluating whether attackers can exploit explainability to evade detection. All failure modes are recorded transparently.

> **Academic Framing (from `docs/research-gap.md`):**  
> *"In the literature reviewed for this project, we did not find a single locally-deployable, budget-constrained student system that combines multi-signal explainable phishing risk scoring with an explicit AI-authorship indicator and a self-directed adversarial evasion test. The individual techniques are established; the integration and the honest reporting of their limits is the contribution."*

## 2. Technical Stack Specifications

| Subsystem | Technology Selection | Rationale / Constraints |
| :--- | :--- | :--- |
| **Backend Framework** | FastAPI (Python 3.11+) | Async high-performance REST API, automatic OpenAPI validation via Pydantic |
| **Data Persistence** | SQLite + SQLAlchemy 2.0 | Zero-config, zero-cost, local relational persistence for email analyses and metrics |
| **Email Parsing** | Python standard `email` + BeautifulSoup4 | Safe parsing of RFC-822 / MIME emails, HTML body sanitization, zero execution |
| **URL Analysis** | `urllib.parse`, `tldextract`, custom regex | Purely static analysis: IP hosts, Punycode, suspicious TLDs, entropy, token deception. **Never fetched** |
| **Attachment Inspector**| `mimetypes`, `hashlib` (SHA-256) | Static inspection: double extensions, executable MIME types, dangerous extensions. **Never executed** |
| **ML Baseline** | `scikit-learn` (TF-IDF + Logistic Regression) | Deterministic, auditable baseline with calibratable probability output |
| **Explainable AI (XAI)**| SHAP (`LinearExplainer`) + LIME (`LimeTextExplainer`)| Token-level importance attribution with transformation to natural language explanations |
| **AI Authorship Detection**| Stylometric feature extractor + Scikit-learn Classifier | Measures lexical diversity, syntactic variance, punctuation ratios, function words, Flesch scores |
| **Adversarial Evaluator**| Explanatory perturbation engine + re-scoring pipeline | Measures perturbation evasion rates against SHAP-directed feature removal |
| **Risk Engine** | Weighted Multi-Factor Heuristic Aggregator | Configurable 100-point risk score with categorical severity thresholds |
| **Security Reporting** | ReportLab | Server-side cryptographic hash-stamped PDF forensic report generation |
| **Frontend UI** | React 18 + Vite + Tailwind CSS + Recharts + Lucide | Professional SOC analyst UI, accessible color/text/icon telemetry, dark/light theme |

## 3. Risk Engine Weights & Severity Thresholds

Risk scoring follows a modular, weighted allocation totaling 100 points:

| Component Factor | Default Weight | Key Analytical Signals |
| :--- | :--- | :--- |
| **ML Phishing Probability** | 30 | Probability output from calibrated TF-IDF + Logistic Regression model |
| **URL Static Risk** | 20 | IP addresses, @-deception, excessive subdomains, brand-in-subdomain, suspicious TLDs |
| **Header & Authentication** | 15 | SPF/DKIM/DMARC status, Reply-To mismatch, Return-Path divergence, spoofed display names |
| **Sender/Domain Anomalies** | 10 | Typosquatting distance (Levenshtein), lookalike Unicode characters, mismatched domain names |
| **Social Engineering Triggers** | 10 | High urgency, fear-appeal, credential requests, authority impersonation, financial pressure |
| **Attachment Risk** | 10 | High-risk extensions (`.exe`, `.scr`, `.vbs`, `.iso`), double extensions (`.pdf.exe`), office macros |
| **Content Anomalies** | 5 | Invisible characters, hidden text, massive whitespace padding, obfuscated HTML tags |
| **Total** | **100** | Scaled compound security score |

### Categorical Risk Tiers:
- **0 – 24 (LOW):** Minimal anomalies; legitimate organizational markers verified.
- **25 – 49 (MODERATE):** Isolated anomalies detected; manual scrutiny suggested.
- **50 – 74 (HIGH):** Strong malicious indicators across multiple vectors; quarantined.
- **75 – 100 (CRITICAL):** Multiple definitive phishing hallmarks; immediate containment required.

*Note: AI-Authorship likelihood (0–100%) and Adversarial Robustness metrics are reported alongside the risk score as independent analytical dimensions, not blended into the 100-point security score.*

## 5. Security & Safety Invariants

1. **NO CODE EXECUTION:** Under no circumstances will uploaded attachments, macro scripts, or embedded objects be executed or interpreted.
2. **NO URL FETCHING:** No network requests (GET, HEAD, DNS resolution, or crawler requests) will be issued to parsed URLs.
3. **ISOLATED SANDBOXING:** All file hashes and MIME types are calculated statically via streaming buffered file handles.
4. **NO THIRD-PARTY API LEAKS:** Zero telemetry, email content, or parsed headers will be transmitted to external commercial LLMs or APIs.
